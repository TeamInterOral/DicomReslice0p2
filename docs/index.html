Implant Studio: “The distance between the layers in file … is incorrect (Expected = 0.200 mm vs Actual = 0.400 mm)” — how to fix it

A practical fix for the 3Shape Implant Studio DICOM import error caused by non-uniform CT/CBCT slice spacing. By Team InterOral.

The exact error message

When you import a CT/CBCT scan into 3Shape Implant Studio (or Implant Planner), the scan lands under “Unsupported scans” and the panel shows a message like this:

The distance between the layers in file 00000176.dcm and file 00000178.dcm is incorrect. Expected = 0.200mm vs Actual = 0.400mm.

You may also see, in the same dialog:

Unsupported scans 4 files haven't been loaded due to an error: Error processing tag X100B5802

The scan appears under “Available CT scans” / “Unsupported scans”, the volume size reads something like 600x600x446, and the Select button stays unavailable. In our case the scanner reported as T2 Plus, but this is not scanner-specific.

Why it happens

Implant Studio requires the CT/CBCT series to have a uniform distance between slices (a constant slice increment) — this is part of its DICOM import requirements. The error means that somewhere in the stack two neighbouring slices are spaced differently than the rest:

  • The series declares a slice spacing of 0.200 mm, but between two specific files the actual gap is 0.400 mm (a missing/irregular slice, or mixed spacing in the export).
  • Because the geometry is not regular, Implant Studio refuses to load it (and a few files may fail tag processing — the Error processing tag line).

This typically comes from how the scan was reconstructed / exported from the CBCT software — the slice increment is not perfectly constant across the whole stack. Re-exporting does not always fix it.

The fix: resample the series to a uniform 0.2 mm spacing

The reliable solution is to resample the DICOM volume onto a uniform 0.2 mm grid and export it as a new, clean DICOM series — then import that into Implant Studio.

We built a small, free Windows tool that does exactly this in one click. It drives a local 3D Slicer installation to reload the scan and re-slice it uniformly at 0.2 mm, writing a new DICOM series to a corrected folder.

⬇ Download DicomReslice0p2 (free) View source on GitHub

Steps

  1. Install 3D Slicer (5.x) on the PC, if it isn’t already.
  2. Download and run DicomReslice0p2.exe from the Releases page.
  3. Pick the folder that holds your DICOM series. (Slicer.exe is auto-detected.)
  4. Keep Spacing = 0.2 and click Run.
  5. Import the new series from the corrected sub-folder into Implant Studio — it now loads as a supported scan.

Patient and study information are preserved; the output is a new series. Original files are left untouched. A run log is saved next to the output.

Alternative: do it manually in 3D Slicer

If you prefer not to use the tool, you can reproduce the same fix by hand:

  1. Open 3D Slicer and load the DICOM series (DICOM module → Import → Load).
  2. Go to Modules → Resample Scalar Volume.
  3. Set Output pixel spacing to 0.2, 0.2, 0.2 (mm), interpolation linear, and run.
  4. Export the resampled volume as a new DICOM series (DICOM module → Export), then import that into Implant Studio.

FAQ

What does “Expected = 0.200mm vs Actual = 0.400mm” mean?

The series is supposed to have 0.200 mm between every slice, but between two specific slices the real gap is 0.400 mm. The slice spacing is not uniform, so Implant Studio rejects the scan.

What is the “Error processing tag X100B5802 / 4 files haven’t been loaded” message?

It appears together with the slice-distance problem: a few files in the irregular stack fail to load. After resampling the volume to a clean, uniform series the new export imports without these errors.

Will this change my scan’s quality?

Resampling interpolates the volume onto a uniform 0.2 mm grid. If the data is already close to 0.2 mm the change is minimal; the goal is a geometrically regular series that Implant Studio accepts.

Does this work for other scanners, not just T2 Plus?

Yes. The error is about DICOM geometry (non-uniform slice increment), not a specific scanner, so the fix applies regardless of the CBCT/CT device.

Is it free and safe?

Yes — the tool is free and open source. The processing runs locally through your own 3D Slicer; nothing is uploaded. You can verify the download with the published SHA-256 checksum.
